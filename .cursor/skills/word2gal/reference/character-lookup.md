# 角色形象网查（内部）

> 验收标准第 2 条：按文中人物上网查对应长相，再生成符合长相的立绘。

## 原则

**先查后画。** 禁止在未尝试检索的情况下，凭模型记忆或乱编外貌出立绘（无联网环境除外，见回退）。

## 步骤（每个主要角色）

### 1. 构造查询

优先顺序：

1. `作品名 + 角色名 + 立绘/官方图`（若文章能判断作品）  
2. `角色名 + 外貌关键词`（发色、发型、服装）  
3. 若判定为 OC：不搜「同名动漫角色」硬凑；改为「按文内描写生成」，`lookup=fallback`

### 2. 执行检索

使用当前环境可用的联网能力（网页搜索、图片结果、资料页等）：

- 收集 1～3 个通行形象要点：发型、发色、瞳色、常服、标志物  
- 若能得到参考图 URL/本地图，记下供出图 `reference_image`  
- 注意同人敏感与版权：仅作**形象参考生成新立绘**，不要原样盗用官方图进成品商业分发说明；交付时说明「参考通行设定重新绘制」

### 3. 写入角色卡

见 `character-card.md`，必须含：

- `lookup`: `web` | `fallback` | `offline`
- `referenceNote`: 一句话说明查到了什么，或为何回退
- 短参数 `hair` / `eyes` / `outfit` / `vibe`（从检索结果或文内描写蒸馏，**不要**把网页长文塞进 prompt）

### 4. 出图

1. 有参考图 → 以参考图约束 + `style-packs/.../prompt.md` 生成半身立绘  
2. 无参考图但有检索要点 → 短参数 + 风格包  
3. 均失败重试 ≤2 → defaults，并在摘要中点名该角色

## 一致性

- 同一角色所有表情差分必须基于同一基准立绘/同一套短参数 + 参考  
- 禁止每张表情重新「换脸」

## 无联网 / 检索失败

```
lookup = offline 或 fallback
```

- 仅用文章 `appearanceClues` 蒸馏  
- **必须**在交付摘要用自然语言告诉用户：哪些角色未能网查、已按文内描写生成
