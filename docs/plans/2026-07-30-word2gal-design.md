# Word2Gal 设计说明

## 背景与目标

面向同人创作者的 **Cursor Agent Skill**：用户只用自然语言描述剧情与角色，Skill 指导 Agent 产出浏览器可直接打开的单文件 HTML 视觉小说（对话框、立绘、选项分支、短反应音、基础存档）。

成功标准（MVP）：

1. 用户只输入自然语言，得到可双击运行的 `.html`
2. 可完成对话推进、立绘表情切换、选项分支、存读档
3. 主要角色有风格包约束下的可看半身立绘；失败则默认立绘且不白屏
4. 关键情绪句可播标签化短反应音；无音不阻断阅读
5. 不要求用户填写 JSON、标记语法或资源路径

## 现状与约束

- 仓库起点：`Word2Gal.md` 愿景文档；交付形态是 **Skill**，不是独立大工程/平台
- 硬约束：
  - **对外全自然语言**；剧本 JSON、角色卡、emotion/voiceTag 仅在 Agent 执行层存在
  - 声音：仅标签化短反应音，不对白全文 TTS
  - 立绘：强约束风格包（参数卡出图，禁止自由长描述直出）
  - 稳定优先：素材失败可回退，玩法必须可玩
- 非目标（首版不做）：后端服务、素材中台、全文 TTS、Live2D、口型、复杂粒子、用户手写播放器逻辑

## 方案对比

### 方案一：Skill 编排 + 固定播放器模板 + 可控资产步骤（推荐）

- 优点：下限稳；播放器不靠模型临场写 JS；可分步重试素材；贴合 Skill 体量
- 缺点：需维护模板与风格包提示词

### 方案二：重模板轻生成（部件/预制差分）

- 优点：几乎不翻车、成本低
- 缺点：OC 辨识度弱；偏离「按描述生成角色」

### 方案三：端到端一次吐完整 HTML

- 优点：看似快
- 缺点：质量不可控，与「不尴尬」冲突

## 推荐方案

采用 **方案一**，并吸收方案二作安全网（默认立绘/默认短音库）。

一次出片体验（用户视角的 C），内部仍分步：解析 → 角色卡 → 立绘/短音 → 填模板打包；任一步素材失败则回退默认资源，HTML 仍可运行。

## 详细设计

### 架构（Skill 体量）

```
用户自然语言
    → Skill 分步指令（Agent 执行）
        1. 解析为内部剧本 JSON
        2. 蒸馏角色参数卡 + 选用风格包
        3. 按风格包生成/选用立绘差分与短反应音
        4. 填入固定 HTML 播放器模板并内联资源
    → 单文件 HTML（模式一）；模式二换高级演出模板复用同一剧本
```

四层含义（实现上均为 Skill 文件与 Agent 步骤，非微服务）：

| 层 | Skill 中的实体 |
|---|---|
| 输入层 | 用户自然语言（剧情 + 可选人设/风格口语） |
| 编排层 | `SKILL.md` 分步流程 + 自检清单 |
| 运行时层 | `templates/player-basic.html`（及后续 advanced） |
| 资产层 | `style-packs/` 提示词与默认图/音 + 生成结果内联 |

### 关键组件

1. **`SKILL.md`**：触发条件、自然语言输入约定、分步工作流、质量底线、回退规则
2. **内部剧本 schema**（`reference/script-schema.md`）：`scene` / `narration` / `dialogue` / `choice` / `ending`；`dialogue` 含 `emotion`，可选 `voiceTag`
3. **角色卡**（内部）：`id`、显示名、风格包、外观参数、表情集合、音色预设档
4. **风格包**（首版 1 套主包）：半身/透明底/统一画幅、固定负面词、表情差分出法、默认回退资源、对话框皮肤与节奏；四大叙事风格首版主要换 UI/节奏，不急四套画风
5. **播放器模板**：原生 HTML/CSS/JS，无外部依赖；逻辑写死，Agent 只注入剧本与资源
6. **模式二模板**（可后置）：转场、震动、字体动画、BGM 槽；不重解析剧本

### 数据流 / 接口

**用户可见输入（仅自然语言）示例意图：**

- 剧情正文，可口语说明「这里两选一」「两个结局」
- 角色外貌与性格散文
- 「偏日常治愈」「加强演出」等偏好

**Agent 内部产物（用户不手写）：**

- `script` JSON（稳定 `nodeId` 跳转）
- `characters[]` 参数卡
- 资源映射：`char_{id}_{emotion}.png`、`sfx_{voiceTag}.*`、`bg_{sceneId}.*`
- 最终：将 script + 资源（base64 或同目录约定）写入模板占位符，输出 `.html`

**失败回退：**

- 立绘/音质检不通过 → 有限重试 → `default_*` 资源
- 剧情含糊 → 自然语言追问 1～2 句，或默认单线并在摘要说明

### 异常与边界处理

- 角色描写过少：风格包默认人设补全
- 角色过多/文本过长：软上限（建议主角 ≤4、短篇）；超出提示拆篇或降配
- 浏览器自动播放限制：需用户首次点击后再播短音
- 体积过大：压缩图/音或外置资源仍对用户表现为「一个成品目录/一页说明」
- 违规内容：按模型/平台策略拒绝或降级

原则：**玩法可用性 > 素材完美**；可「只补资产」重跑，不必重写故事。

### 测试策略

- 样例自然语言 → 内部剧本：节点完整、选项可达、无死链（可用小型校验脚本或清单）
- 播放器夹具：无素材 / 缺素材 / 全素材，手测主路径与存读档
- 立绘抽检同角色多表情一致性；短音抽检时长与标签
- Chrome/Edge 打开单文件 HTML
- Skill 路径：全程不要求用户填格式

## 风险与待确认项

| 风险 | 缓解 |
|---|---|
| 文生图仍偶发崩坏 | 风格包强约束 + 重试 + 默认立绘 |
| 单文件体积膨胀 | 限差分数量、压缩、短音极短 |
| Agent 临场改播放器逻辑 | Skill 明确禁止；只允许填占位符 |
| 出图/出音依赖外部环境 | Skill 写明可用工具与无工具时的占位策略 |

待实施时确认（不阻塞设计）：Skill 安装位置（项目内 `.cursor/skills/word2gal` 优先）；首套风格包画风关键词定稿。
