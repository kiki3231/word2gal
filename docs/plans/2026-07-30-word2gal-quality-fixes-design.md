# Word2Gal 质量三项改进 设计说明

## 背景与目标

近期成品暴露三类问题：

1. 立绘抠图不干净（残绿/灰底/棋盘格），或半残底上架。
2. 拟声缺少笑、叹等人口技，听感像单调机械咚哐。
3. 剧本对白/旁白被简化，与用户原文不一致。

成功标准：

- 立绘优先真透明；抠不干净则绿幕回退；不过自检不上架。
- 口技与文中有据的轻环境音并存；禁止用打击音冒充口技。
- 对白/旁白/内心独白原文保真，交付前做覆盖自检。

## 现状与约束

- `SKILL.md` / `daily-heal/prompt.md` 当前强制「纯绿幕 → cut-sprite」，与「优先透明」目标冲突。
- `cut-sprite.mjs` 头部注释已偏向「透明优先、抠图回退」，文档未对齐。
- `emotion-and-sfx.md` 列了笑/叹标签，但未写生成提示与环境音边界，Agent 易生成错误音类。
- `extraction.md` 已写「禁止压缩原文」，缺可执行的覆盖自检步骤。
- 文生图工具写 `transparent` 时常画出棋盘格假透明——故保留绿幕回退，而非完全弃用抠图。

## 方案对比

### 方案一：只改文档约束
- 优点：改动小
- 缺点：缺可执行自检

### 方案二：文档 + 轻量自检（采用）
- 优点：与现有 validate / cut-sprite 衔接，规则可执行
- 缺点：原文覆盖以 Agent 清单为主，全自动字级 diff 暂不做

### 方案三：预置音效库 + 大改抠图管线
- 优点：音质稳定
- 缺点：用户已否决「以预置库为主」；超出本次范围

## 推荐方案

采用方案二，三条路径均为用户确认的 **A**：

| 项 | 决策 |
|----|------|
| 立绘 | 真透明优先；绿幕+抠图仅回退；自检不过重做 |
| 拟声 | 口技必须到位 + 允许文中有据的轻环境音；禁止环境音冒充口技 |
| 剧本 | 原文逐句进戏，仅可原样切开；覆盖自检必做 |

## 详细设计

### 架构

不改播放器核心 JS。仅更新 Skill 工作流文档、风格包提示，并可选增加轻量资源自检脚本（立绘 alpha 抽检）。Bake 仍走 `validate-script` → `bake-story`。

### 关键组件

1. **立绘路径（Agent + 风格包）**
   - 默认：无场景底板生图，争取真透明 PNG；禁止提示 checkerboard。
   - 回退：实心底/假透明 → 绿幕重生 + `cut-sprite --mode green`；浅灰底急救用 flood。
   - 门槛：残绿/灰白/棋盘格 → 禁止 Bake。

2. **拟声（emotion-and-sfx）**
   - `vocal`：笑、叹、惊呼、轻哼、哽咽等。
   - `foley`：脚步、敲门、门开合、衣料轻响等（须有原文依据）。
   - 生成提示分模板；负面约束禁止无依据堆砌打击/轰鸣。
   - 「笑了/叹了」必须挂人口技，不得用咚哐替代。

3. **原文保真（extraction + 验收）**
   - `text` 必须可在原文定位；只允许切开。
   - 交付前：关键句覆盖自检；超软上限拆章，禁止摘要浓缩。

### 数据流 / 接口

```
原文 → 抽取(保真 beats) → 成色+拟声清单(vocal/foley)
     → 角色卡/生图(透明优先|绿幕回退) → alpha 自检
     → 拟声生成(按类提示) → validate-script → bake-story
```

剧本字段不变：`voiceTag` 仍为字符串；清单在 Agent 内部区分 vocal/foley 即可，无需改 JSON schema（除非后续要强制枚举）。

### 异常与边界处理

| 情况 | 处理 |
|------|------|
| 生图棋盘格/假透明 | 绿幕重生 + 抠图；仍失败 → defaults |
| 抠后残边 | 重抠或重画，不上架 |
| 口技听感像打击乐 | 重生成或静音回退 |
| 环境音无原文依据 | 不挂 |
| 超字数 | 拆章分次，禁止浓缩 |

### 测试策略

- 文档验收清单更新（SKILL 第 7 步）。
- 可选：`check-sprite-alpha.mjs` 检查 PNG 是否存在透明像素（非全不透明底板）。
- 拟声/原文覆盖以交付摘要自检项约束（本轮不做全文 diff 脚本）。

## 风险与待确认项

- 文生图对「无底板」支持不稳定 → 绿幕回退必须保留且文档写清。
- 环境音尺度主观 → 用「短、轻、有原文依据」约束，宁缺毋滥。
- 以上设计已经用户分段确认（立绘 A、拟声修订版、剧本 A）。
